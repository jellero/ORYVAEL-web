Core thesis

AI may reason about the system.
It does not own the system.

ORYVAEL separates intelligence from authority. AI components can analyze requirements, write code, test, inspect security, diagnose failures and prepare changes — while capabilities, policy, verification and root trust remain explicit and independently enforceable.

System model

Authority is a stack,
not a superuser account.

Every privileged transition crosses an explicit boundary. No model belongs to the root of trust.

01

Human governance

Constitutional policy, root trust, recovery and irreversible authority remain human-controlled.

02

AI control plane

Agents reason, develop, test, inspect and propose actions as scoped principals.

03

Verification + policy

Deterministic policy, evidence and independent verification decide what may cross privileged boundaries.

04

System services

Applications and native services receive narrow capabilities rather than ambient authority.

05

ORYVAEL kernel

Memory, scheduling, IPC, networking and hardware enforcement form the native runtime boundary.

Running today

Not a Linux distribution.
A native operating system.

The current development image boots directly on x86_64 UEFI and leaves firmware boot services behind before entering the ORYVAEL runtime.

01

Native kernel

Freestanding Rust kernel, physical frame allocator, kernel heap and ORYVAEL-owned PML4 root.

02

Privilege separation

GDT/TSS, exception gates, timer interrupts, DPL3 syscall gateway and verified CPL3 execution.

03

Capability primitives

Capability-checked IPC mailbox and native RAM filesystem prove the initial authority boundary.

04

Native networking

RTL8139, ARP, DHCP, IPv4, ICMP, DNS lookup and a deliberately small TCP implementation.

05

Secure remote access

SSHv2 with Ed25519 public-key authentication and separate system/admin identities.

06

Measured, not claimed

Boot and runtime behavior are exercised by automated integration checks under QEMU.

Continuous security

Reason continuously.
Authorize deterministically.

ORYVAEL is designed so native AI can continuously inspect code, runtime behavior and system evidence without receiving unrestricted administrative power.

01Observetelemetry · code · provenance · behavior
02ReasonAI analysis · correlation · vulnerability detection
03Verifyevidence · independent checks · policy
04Enforceallow · deny · isolate · require human approval

Deny by default

Missing authority is a denial, not an invitation to infer permission.

No self-grant

An AI principal cannot expand its own capabilities or promote itself into the root of trust.

No self-approval

The component implementing a privileged change cannot be the authority that approves it.

Evidence before release

Privileged changes are expected to carry reproducible evidence and independent verification.

Auditable actions

Authority should be attributable, observable and reconstructable after the fact.

Human recovery

Critical recovery paths must remain independently available to humans.

Native Phase 2

Identity, isolation
& native intelligence.

Before native AI receives meaningful system access, ORYVAEL builds the authority substrate that constrains it: process isolation, kernel objects, capabilities, principals, sandboxing, generated keys, authenticated sessions and attributed audit.

01

Process + object substrate

Multi-process scheduling, per-process address spaces, recoverable faults and non-forgeable kernel-managed handles.

02

Principals + capabilities

Humans, services, apps and AI become explicit principals governed by narrow object-specific rights rather than ambient root authority.

03

Secrets + sessions

Entropy, CSPRNG, generated identities, secret-signing capabilities and authenticated sessions replace source-embedded private keys.

04

Governed native AI

Ring-3 AI workers inspect, develop and analyze through capability-enforced APIs, requesting temporary authority when action is required.

05

Sandbox-native workloads

Isolation is a property of process, object visibility, capability tables and resource budgets — not an optional container around the workload.

06

Evidence as exit criteria

The phase completes when AI can detect a condition, request authority, receive a scoped grant, act and leave auditable evidence without self-grant.

Full technical roadmap ↗
  1. Now
    Generalize the native substrate

    Owned page tables, process contexts, recoverable faults, APIC/IOAPIC and capability object tables.

  2. Next
    Become a real application platform

    Persistent storage, filesystem services, general sockets, entropy/key provisioning and multi-process scheduling.

  3. Then
    Port real software

    Compatibility layers and upstream applications with narrow, explicit ORYVAEL capabilities.

  4. Goal
    Run governed native intelligence

    AI workers at ring 3, policy and audit services, continuous security analysis and human-governed release flows.

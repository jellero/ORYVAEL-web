HMI & dedicated systems

Known hardware.
Explicit authority.

Human-machine interfaces, kiosks and dedicated appliances are a natural ORYVAEL target: constrained hardware, a small application surface and behavior that can be described precisely.

Why it matters ORYVAEL can demonstrate its security model on useful products before it must solve the full compatibility surface of a general-purpose desktop.

Why HMI fits

Smaller compatibility problem.
Stronger security signal.

An HMI does not need arbitrary PC hardware and tens of thousands of desktop applications. A defined board and defined workload let ORYVAEL focus on the properties it is designed to prove.

01

Controlled hardware

Support a narrow reference matrix instead of every GPU, NIC, input controller and peripheral from day one.

02

Declared behavior

UI, telemetry, updater and network services have clear responsibilities that map naturally to capabilities.

03

Constrained attack surface

A compromised interface process should not inherit updater, secret, policy or unrelated device authority.

04

Useful AI context

Native AI can correlate telemetry, software state and security evidence without becoming the safety controller.

Authority layout

The interface is not the machine.

A graphical process can be compromised without automatically compromising the updater, device identity, machine secrets or deterministic controller.

Compromise containment

If the UI parser, browser surface or visualization code is exploited, the attacker inherits the UI principal's capabilities — not an implicit root account.

  • machine keys remain outside the UI process
  • updates stay signed and policy-gated
  • device access is object-specific
  • security events remain attributed
  • recovery remains independently available

Consumer appliances

TV is possible.
HMI is the cleaner first target.

A television uses many of the same concepts, but commercial media devices add difficult proprietary integration requirements that are not necessary to validate the ORYVAEL architecture.

GOOD FIT

Capability-isolated apps

A streaming app can receive display, audio and service-specific network authority without access to unrelated credentials or devices.

HARDWARE

Media acceleration

Real TVs depend on GPU/video decode, audio pipelines, HDMI, remote input, Wi-Fi and Bluetooth integration.

ECOSYSTEM

DRM and certification

Protected media, HDCP-class requirements, codec licensing and streaming certification can be commercial constraints independent of kernel quality.

Safety boundary

Secure HMI is not automatically
a safety-certified controller.

Initial ORYVAEL HMI targets should keep deterministic or certified physical control in a separate controller when failure could cause physical harm.

ORYVAEL HMIvisualization · diagnostics · operator commands · cybersecurity
capability-governed command interface
CONTROL DOMAINPLC / certified controller / deterministic safety logic
Engineering rule Do not claim safety-critical control until real-time guarantees, fault models, certification requirements and hardware assumptions are explicitly designed and verified.

Development path

The graphics spike has
a practical destination.

The first framebuffer experiment is not merely visual polish. It can become the first step toward a constrained display service and an HMI reference platform.

  1. 01 · NOW
    Framebuffer bring-up

    UEFI GOP handoff, retained framebuffer descriptor, software backbuffer and deterministic 2D primitives.

  2. 02
    Display abstraction

    Move direct framebuffer ownership behind a kernel/device boundary and expose controlled surfaces.

  3. 03
    Input service

    Keyboard, pointer and touch events become explicit input objects rather than ambient device access.

  4. 04
    Simple compositor

    Compose isolated application surfaces without giving applications raw framebuffer memory.

  5. 05
    HMI shell

    Build a reference interface with telemetry, security state and capability-aware operator actions.
